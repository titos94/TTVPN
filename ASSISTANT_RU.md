# Помощник TTVPN: текущий статус

В локальном коде предусмотрен необязательный текстовый помощник для вошедших
клиентов. Он не видит аккаунты, оплаты, конфигурацию панели или состояние
серверов и не умеет выполнять команды. Данные платежей и ключи автоматически
модели не передаются. Ответы модели могут содержать ошибки.

## Подключение API

Ключ провайдера задаётся в интерфейсе: **Настройки → Искусственный интеллект**
(страница `/settings`, секция `settings-assistant`). Доступна только роли
`admin`; все изменения идут через `POST` с CSRF-заголовком `X-Backup-CSRF`.

Порядок источников:

1. Переменная окружения `TTVPN_ASSISTANT_API_KEY` — **имеет приоритет** над
   сохранённым ключом; в этом случае в интерфейсе показывается плашка
   «ключ из окружения», а сохранённый в панели ключ не используется.
2. Ключ, сохранённый в настройках панели (`settings.assistant` в `data.json`).

Помощник включается **только** при явном согласии: либо `enabled=true` в
настройках вместе с сохранённым ключом, либо `TTVPN_ASSISTANT_ENABLED=1`
вместе с ключом из окружения. Один лишь ключ, без явного включения, помощника
не активирует.

`TTVPN_ASSISTANT_MODEL` необязателен; значение по умолчанию — `gpt-4.1-mini`.
Модель из настроек панели валидируется по шаблону `^[A-Za-z0-9._:-]{1,64}$`.

### Как хранится ключ

Открытый ключ на диск не попадает. В `data.json` лежит только шифротекст
(`api_key_encrypted`) и последние четыре символа для маски (`key_last4`).
Шифрование — Fernet (AES-128-CBC + HMAC-SHA256), ключ шифрования выводится
через HKDF-SHA256 из `SECRET_KEY` панели с фиксированной солью
`ttvpn-assistant-key-v1` и назначением `api-key-encryption`.

Следствия, которые нужно знать при эксплуатации:

- **Смена `SECRET_KEY` делает сохранённый ключ нечитаемым.** Помощник
  выключится, потребуется ввести ключ заново — это ожидаемое поведение.
- **Без `SECRET_KEY` сохранить ключ нельзя**: эндпоинт отвечает `503` с
  русским текстом, панель при этом продолжает работать.
- Резервные копии `data.json` содержат шифротекст. Компрометация бэкапа без
  `SECRET_KEY` не раскрывает ключ, но компрометация `SECRET_KEY` — раскрывает.

Ключ никогда не возвращается в браузер: `GET /api/settings/assistant` отдаёт
только `key_configured`, `key_last4` и статус. Пустое поле ключа при
сохранении означает «оставить текущий ключ». Кнопка «Удалить ключ» очищает
`api_key_encrypted`, сохраняя остальные настройки.

Запросы отправляются на `https://api.openai.com/v1/chat/completions`; форма
предупреждает клиента о передаче сообщения внешнему сервису и требует его
согласия. Перед включением проверьте применимость правил конфиденциальности,
сроки хранения у провайдера и доступность API из соответствующего региона.

### Проверка подключения

`POST /api/settings/assistant/test` выполняет дешёвый запрос
`GET https://api.openai.com/v1/models` с текущим ключом (таймаут 20 с,
редиректы запрещены) и возвращает `{ok, message}`. Ключ, заголовок
`Authorization` и тело ответа провайдера **не логируются**. Одновременно
может выполняться только одна проверка.

Фильтр отклоняет некоторые типовые секреты, но **не гарантирует** обнаружение
всех персональных данных, паролей и ключей. Не отправляйте их помощнику.
Для реального включения необходимы действующий ключ и отдельная проверка
стоимости запросов, ограничений и обработки данных. Пока явное включение или
ключ отсутствуют, форма не показывается. Общий бюджет запросов пока не
реализован, поэтому включать функцию в production преждевременно.

## Диагностика

`GET /api/assistant/health` и `GET /api/assistant/monitor` доступны только
администратору. Неизолированная фоновая проверка **по умолчанию отключена**.
При явно заданном `TTVPN_INPROCESS_MONITOR_ENABLED=1` она раз в минуту наблюдает
свободное место, нагрузку и состояние процесса Telegram-бота; предупреждения
показываются в панели и журнале приложения. Не включайте этот режим, если
монитор должен быть изолирован от данных панели. Он не проверяет доступность VPN-нод, маршрутизацию,
оплату, доставку писем или работоспособность самого API модели.

Проверка больше не открывает базу биллинга. Однако сейчас монитор исполняется
в процессе панели, поэтому изоляция прав на уровне ОС ещё не реализована:
нельзя утверждать, что он технически лишён доступа к платёжным данным или
ключам. Для этого нужен отдельный непривилегированный процесс без доступа к
томам данных и с ограниченным каналом обезличенных метрик.

Из автоматических исправлений предусмотрен только запрос на запуск уже
включённого в панели остановленного Telegram-бота. Повтор — не чаще раза
в пять минут; перед запуском повторно проверяются текущие настройки. Это не
гарантирует успешный запуск: неверный токен или недоступный Telegram API
требуют вмешательства. Действия отражаются в журнале и статусе монитора.

Внешних уведомлений и интеграции с Telegram-чатом поддержки **пока нет**.

## Границы доступа

Помощник — клиентский текстовый ассистент. Он **не** читает аккаунты, оплаты,
конфигурацию панели и состояние серверов и **не** выполняет команды.

Для встроенного ИИ-администрирования (см. `TERMINAL_RU.md`) действует отдельное
правило владельца: ИИ имеет полный доступ к диагностике и управлению, **кроме
API-ключей и секретов**. Реализует это `terminal_policy.py`: команды, читающие
`data.json`, `.env`, `billing.db`, приватные ключи SSH и VPN, переменные
окружения и заголовки `Authorization`, для ИИ запрещены и заменяются отказом.
Вывод любой команды проходит через `redact_output`, который маскирует
секреты перед показом модели и человеку.
