# TTVPN — правила совместной работы агентов

Файл-координатор для параллельной работы нескольких агентов в одном
репозитории (`panel-fork/`). Обновляйте раздел «Журнал», прежде чем начать и
после завершения блока работ.

## Правила

1. **Один файл — один владелец в единицу времени.** Файлы передаются другому
   агенту только явной записью в журнале («владелец → агент X»).
2. **Перед началом** прочитайте `TTVPN_TECHNICAL_AUDIT.md` и этот журнал.
3. **Не менять**: `app.py` (кроме согласованных точек), `data.json`,
   `billing.db`, `.env`, production, Caddy, Docker volumes.
4. **Проверка перед сдачей**: `python3 -m py_compile` для Python, рендер
   Jinja2 для шаблонов, `pytest` для затронутых тестов. Артефакты проверки
   указывать в журнале; не объявлять работу протестированной без запуска.
5. **Не выводить секреты** в чат, логи, коммиты и тесты.
6. Ветка разработки: `develop`. Коммиты — локальные, без push.
7. Тесты запускать только в изолированном окружении (`/tmp/ttvpn-venv`),
   никогда на production.

### 2026-11-06 · ORCHESTRATOR/BACKEND (третья итерация)

Владелец: `billing/store.py`, `billing/provision.py`, `billing/router.py`,
`templates/billing_my.html`, `tests/test_billing_devices.py`, `BILLING.md`
(после сдачи DOCS-агента), этот журнал.

- **Второй профиль на устройство.** `provision.add_device_profile()` +
  `POST /api/billing/devices/{device_id}/profiles`. Сервер берётся из самого
  устройства, протокол — из установленных AWG-протоколов сервера, ещё не
  привязанных к устройству (`provision.profile_options`). Потолок
  `MAX_PROFILES_PER_DEVICE = 3`. Требуется активная подписка (403 иначе).
  Новый peer создаётся через `peer_creates.create`, затем связывается
  `store.attach_connection`.
- **`attach_connection` переносит профиль.** Удаляет прежнюю связь перед
  вставкой, поэтому одно подключение не может занимать два слота.
- **`store.device_for_connection()`** — создание устройства и связи в одной
  транзакции (устраняет окно, в котором наблюдатель видел пустое устройство,
  а параллельный `ensure_devices` мог его удалить).
- **`ensure_devices` чище собирает мусор:** сначала снимает связи с
  исчезнувшими peer'ами, затем удаляет устройства без профилей.
- **Имя peer'а учитывает журнал.** `_used_peer_names()` добавляет к занятым

## Этап: ИИ-настройки в панели и политика терминала (решения владельца)

Владелец утвердил три решения: ключ модели вводится **в настройках панели**
(защищённое поле, не только `.env`); терминал получает **полный доступ, кроме
критических систем**; для ИИ — **полный доступ, кроме API и ключей**. Дизайн
остаётся за Астрой (`ttvpn-visual`), доступность агента зависит от лимита
подписки ChatGPT.

### Ключ модели в интерфейсе

- **`assistant_settings.py`** (новый модуль): Fernet (AES-128-CBC + HMAC-SHA256)
  поверх ключа, выведенного HKDF-SHA256 из `SECRET_KEY` панели с солью
  `ttvpn-assistant-key-v1` и назначением `api-key-encryption`. Хранится только
  `api_key_encrypted` + `key_last4`; открытый ключ на диск не попадает.
  Валидация: ключ 20..512 печатных ASCII, модель `^[A-Za-z0-9._:-]{1,64}$`,

  смена `SECRET_KEY` делает ключ нечитаемым, приоритет env, `clear-key`) и
  под правило «ИИ без секретов».

Замечание: HTTP-маршруты терминала и экран терминала **не реализованы** —
сначала политика и тесты, затем подключение к панели по согласованию
(это RCE-эндпоинт, нужен второй фактор и read-only монтирование данных).
